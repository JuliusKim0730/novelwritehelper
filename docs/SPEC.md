# 소설 협업 집필 도구 스펙 v0.1

작성일 2026-11-02. 결정이 나는 대로 이 문서를 갱신합니다.

## 개요

웹소설 연재를 기본으로, 작가와 AI가 함께 소설을 기획하고 쓰고 다듬는 웹앱이다. 단편과 장편도 같은 구조로 다룬다. 에세이 등 소설 외 글은 범위에서 제외한다(카드뉴스 프로젝트로 이관).

- 사용자 확장 단계: Julius 1인 사용 → 소수 지인 공유 → 공개 서비스
- 플랫폼: 웹앱(데스크톱 브라우저 우선, 모바일은 읽기와 간단 수정)
- 핵심 원칙: AI 개입 정도는 작가가 정한다. 설정과 본문은 늘 서로 연결되어 있다.

## 핵심 개념과 데이터 구조

| 개념 | 설명 | 주요 속성 |
| --- | --- | --- |
| 작품 | 소설 한 편 | 제목, 형식(웹소설/단편/장편), 장르, 로그라인, 문체 가이드, AI 모드 기본값 |
| 권 / 부 | 큰 묶음(웹소설은 시즌) | 제목, 순서, 요약 |
| 화 / 장 | 연재 단위 | 번호, 제목, 상태(구상/초고/탈고/연재완료), 목표 분량, 연재일 |
| 씬 | 화 안의 장면 | 시점 인물, 등장인물, 장소, 시간, 목적, 본문 |
| 인물 | 인물 사전 항목 | 이름, 별칭, 외모, 성격, 말투 예시, 관계, 성장 메모 |
| 설정 | 세계관 노트 항목 | 분류(장소/세력/마법·기술/용어), 설명, 규칙 |
| 이벤트 | 타임라인의 사건 | 작품 안 시점, 관련 인물, 등장 화, 복선 여부 |
| 버전 | 본문 스냅샷 | 시각, 작성자(사람/AI), 메모, 부모 버전 |

본문에서 인물·설정 이름을 태그하면 역참조가 자동으로 쌓인다.

## 기능 명세

| 모듈 | 핵심 기능 | AI가 돕는 것 |
| --- | --- | --- |
| 세계관 노트 | 분류별 설정 카드, 검색, 본문 등장 위치 | 설정 확장 제안, 모순되는 규칙 알림 |
| 플롯보드 | 권→화→씬 카드 재배치, 화별 상태 표시 | 다음 화 전개 후보 3개, 클리프행어 제안 |
| 인물 사전 | 인물 프로필, 관계도, 등장 화 목록 | 말투 샘플 생성, 비중 분석 |
| 이벤트 타임라인 | 작품 내 시간축 사건, 연재 순서와 사건 순서 비교 | 시간 역전 오류 감지 |
| 집필 공간 | 씬 단위 에디터, 관련 인물·설정 옆 패널, 글자수, 집중 모드 | 이어쓰기, 문단 다듬기, 대안 전개 |
| 검토 도구 | 화 단위 검토 리포트 | 설정 충돌, 말투 일관성, 복선 미회수, 도입부 흡인력 |
| 맞춤법 검사기 | 맞춤법·띄어쓰기 밑줄, 일괄 수정, 작품 전용 사전 | 문맥 기반 교정 |
| 버전 기록 | 자동·수동 스냅샷, Diff 비교, 복원, 갈래 실험 | 버전 간 변경 요약 |

## AI 협업 모드

작품 단위 기본값, 씬마다 변경 가능.

| 모드 | 초안 작성 | AI 역할 |
| --- | --- | --- |
| 조수 | 작가 | 부르면 제안만 |
| 번갈아 쓰기 | 작가와 AI 교대 | 앞 내용과 설정을 이어받아 작성 |
| 다듬기 | 작가 | 문체 가이드에 맞춘 수정 제안(수락/거절) |
| AI 초안 | AI | 플롯 카드 기반 초안, 작가가 수정 |

AI 문장은 버전 기록에 작성자가 표시되고, 수락 전에는 제안 상태로 남는다.

## MVP 범위와 로드맵

1. MVP(1인): 작품/화/씬 구조, 집필 공간, 인물 사전, 세계관 노트, AI 모드 4종, 자동 저장과 기본 버전 기록
2. 구성 강화: 플롯보드, 이벤트 타임라인, Diff 비교, 맞춤법 검사기
3. 품질: 검토 도구, 내보내기(연재용 텍스트, docx/epub)
4. 확장: 공동 작가 초대, 권한, 댓글, 갈래 병합

## 기술 스택 (확정 2026-11-03)

기존 프로토타입의 Firebase를 유지하고 프론트 빌드만 CRA에서 Vite로 옮긴다.

| 영역 | 선택 |
| --- | --- |
| 프론트엔드 | React 19 + MUI 7, Vite 빌드 |
| DB / 인증 / 호스팅 | Firebase (Firestore, Google 로그인, Hosting, GitHub Actions 자동 배포) |
| 보안 | firestore.rules: 문서 주인(userId)만 읽기·쓰기 |
| AI | Claude API, Firebase Functions에서 호출 (API 키는 서버에만) |
| Diff | diff-match-patch 또는 jsdiff |
| 맞춤법 | 한국어 검사기 API 검토 + AI 보완 |

현재 데이터 구조는 chapters / plots / characters 컬렉션이 userId로 사용자에 바로 붙어 있어, 작품 계층 도입 시 구조 변경이 필요하다.
